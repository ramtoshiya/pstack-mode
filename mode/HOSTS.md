# Host adapters {:#hosts}

## Activation {:#process}

The plugin is installed for the user and stays inactive until activated. Run `/pstack-mode:mode` to start the mode in a session, or `$pstack-mode:mode` in Codex. Claude Code, Codex, and Hermes load the same package, but Hermes is an operator, not a coding host, as the Hermes section below describes. The entry skill reads the complete `mode.md` from the installed plugin root. After compaction in Claude Code, the SessionStart hook reloads the mode when the transcript shows the command or the session's first message is a brief that reads a pstack-mode root's `mode.md`. A repository can opt in to automatic activation by setting `PSTACK_MODE=1` in its Claude settings `env`. The SessionStart hook then loads the mode on startup, resume, clear, and compaction. Existing sessions cannot unload instructions they already received. Hermes does not run the hook. On Codex the hook runs only after the user trusts it, and command detection has not been verified. Where the hook does not restore the mode, retain the plugin root in the compaction summary and read `mode.md` again before continuing.

Workers enter the mode through their brief, not through settings or launch environment. A native subagent shares the parent's plugin set but not its conversation. A separate process or BB child thread loads its own configuration. Each receives the absolute `mode.md` and `HOSTS.md` paths in the brief, and the paths resolve on the same machine. A worker that delegates again includes the same paths in its briefs. Keep working-directory assumptions and route state in the compaction handoff.

## Shared routing {:#routing}

Read the shared `ramtoshiya:worker-routing` skill once before spawning. Resolve it through the host's available skills. If the host cannot resolve it, report the installation mismatch instead of inventing another table. The caller keeps its roles, candidate counts, and family constraints.

Use the host's listed model IDs and effort options. Do not carry Cursor model slugs into another host. On Claude Code use `Agent` with `subagent_type: general-purpose`, or the registered `pstack-mode:comment-sicko` for that role. On Codex use `spawn_agent`. Hermes does not spawn workers, as the Hermes section below describes. Preserve read-only role boundaries even when the API has no `readonly` parameter. When the session has no native agent API, start workers with the thread tool that `ramtoshiya:worker-routing` names for the host, such as `bb nest spawn` in BB. Perform the calling skill's roles sequentially, as its fallback permits, only when neither is available. Do not describe sequential passes as independent fresh workers.

For arena, including when architect runs it for a large or contested design, start with two independent candidate seats. Add seats when the design directions need them, as arena prescribes. Select each seat's row by the shared policy. Use different model families when available. A cross-judge must be outside the parent's model family. Claude and GPT are different families even when both run through Claude Code. A claudex `opus` alias is GPT, not Claude. When no other-family judge can run, keep arena's explicit skip-judge fallback and disclose it. Do not silently describe one family as a diverse panel.

## Hermes as operator {:#hermes}

Hermes talks with the user and runs only the conversation workflows: in-your-own-words, why, how, interrogate, statechart, technical-writing, and unslop. It does not implement and does not run worker roles. Do not use `delegate_task`: it runs Hermes's own subagents on Hermes's model, so the role never reaches Claude or GPT. Hand each implementation task or worker role to an external coding agent, such as Claude Code, Codex, or claudex, through the orchestration the host provides. The brief follows the worker rules in `mode.md` and carries the absolute `mode.md` and `HOSTS.md` paths. That agent coordinates the workflow, including arena seats and cross-judges. If no external agent can take the work, report that instead of running the role in Hermes. The sequential fallback does not apply to Hermes.
